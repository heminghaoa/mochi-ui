# Pokoland UI v0.3.0 Release Completion Design

Date: 2026-08-05  
Status: Approved for written review  
Extends: `2026-06-12-react-package-design.md`

## 1. Goal

Complete and publicly release Pokoland UI v0.3.0 without expanding the component API or pulling later-roadmap features into this release.

The release is complete only when all of the following are true:

- the package builds, passes its test suite, and installs from both a local tarball and the npm registry;
- TypeScript consumers can import the public React API and receive the intended type checking;
- the trilingual documentation site is deployed and its core pages work in Chinese, English, and Japanese;
- the existing zero-dependency demo remains functional;
- CI is green on the pushed release commit;
- npm contains `pokoland-ui@0.3.0`;
- Git contains tag `v0.3.0`, and GitHub contains a matching release;
- production URLs and registry installation are verified after publication.

## 2. Scope

### Included

1. Finish package export, declaration, and tarball integrity checks.
2. Add a self-hosted React documentation site that uses the package's own components.
3. Document all public components with live examples, copyable code, props, and accessibility notes.
4. Support Chinese, English, and Japanese throughout the documentation site.
5. Update CI so checks, tests, package builds, and site builds gate GitHub Pages deployment.
6. Synchronize the three READMEs, roadmap, contributor guide, and component documentation.
7. Perform measured, release-blocking optimizations only: package payload, site bundle, image/font loading, and obvious runtime regressions.
8. Publish npm version 0.3.0, push the release commit, deploy Pages, and create the Git tag and GitHub Release.
9. Reinstall from npm in a clean temporary consumer and verify the deployed site and legacy demo.

### Excluded

- Pagination, Skeleton, Stepper, Accordion, night mode, sound effects, Tailwind preset, Figma library, theme generator, and mascot assets.
- Breaking changes to the current React component API unless verification exposes a release-blocking defect.
- Redesigning the existing visual language.
- Publishing any version other than 0.3.0.

## 3. Architecture and Delivery Flow

The existing sources remain authoritative:

- `src/pokoland.css` is the single style source.
- `src/pokoland.js` remains the zero-dependency vanilla entry.
- `src/react/` remains the React and TypeScript implementation.
- `docs-site/` will be a small React SPA that imports `src/react/` directly for dogfooding.

The release flow is:

1. Build `dist/` and inspect the npm payload.
2. Install the local tarball into a clean temporary React consumer and validate runtime imports and TypeScript types.
3. Build and exercise the documentation site in all three languages.
4. Run checks, tests, build, and focused performance measurements locally.
5. Commit and push the release-ready source.
6. Wait for GitHub CI and Pages deployment, then verify production.
7. Publish `pokoland-ui@0.3.0` to npm.
8. Install the registry package in a new clean consumer and re-run the smoke test.
9. Create and push `v0.3.0`, then create the matching GitHub Release.

## 4. Documentation Site

The site will use hash routing so it works under the GitHub Pages project path without server rewrites. It will include:

- a home page with installation and first-use examples;
- grouped navigation for every public component;
- one reference page per logical component group;
- live rendered examples using the current React components;
- copyable source examples;
- props and accessibility guidance;
- persistent Chinese, English, and Japanese selection;
- links to the zero-dependency demo, repository, and package.

The site keeps Pokoland's sticker-and-meadow identity while prioritizing readable documentation, responsive navigation, keyboard access, and low bundle cost.

## 5. Optimization Policy

Optimization is measurement-led and must not delay the release for speculative micro-optimizations. Before-and-after evidence will cover:

- compressed and unpacked npm package size;
- JavaScript and CSS output sizes;
- documentation-site bundle and static asset sizes;
- local browser performance and layout stability for representative pages;
- regressions in keyboard interaction or reduced-motion behavior.

Release-blocking findings will be fixed. Broader refinements will be recorded for a later version when they do not affect v0.3.0 correctness or usability.

## 6. Error Handling and Irreversible Actions

Checks are ordered so irreversible actions happen last:

- any failing check, test, build, tarball install, type assertion, or browser smoke test blocks push and publication;
- a failing CI run blocks production verification and npm publication;
- a failed Pages deployment blocks npm publication until the deployed documentation is healthy;
- npm authentication failure pauses at `npm login` without changing the requested version;
- an npm registry conflict or existing 0.3.0 version stops the release rather than incrementing the version automatically;
- tag and GitHub Release creation happen only after the registry package passes a clean install test.

The user has explicitly authorized the v0.3.0 npm publication, Git push, production deployment, tag, and GitHub Release. No additional publication confirmation is required unless an external authentication step needs user action.

## 7. Verification Matrix

| Boundary | Required evidence |
| --- | --- |
| Source | clean targeted diff; existing user files preserved |
| Unit | complete `bun test` pass |
| Static | `bun run check` and declaration build pass |
| Package | inspected `npm pack --dry-run` payload and clean tarball install |
| Types | valid icon name passes; invalid icon name fails as expected |
| Browser | core docs interactions, three-language switching, responsive layout, and legacy demo smoke pass |
| Performance | package/site size report and representative browser measurements |
| CI | release commit workflow completes successfully |
| Production | Pages root, docs routes, and legacy demo respond and render correctly |
| Registry | npm reports 0.3.0 and a clean consumer installs and renders it |
| Release | pushed `v0.3.0` tag and matching GitHub Release |

## 8. Release Boundary

The final report will distinguish local validation, committed state, pushed state, deployed state, npm registry state, and GitHub Release state. If any boundary cannot be verified, it will be reported as incomplete rather than inferred from an earlier step.
